# 视觉-语言-动作模型 RT-2（RT-2: Vision-Language-Action Models）解读

> 论文：RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control（CoRL 2023；本 PDF 为 arXiv 预印本 v1）
> arXiv：2307.15818｜PDF：papers/02_RT-2_2307.15818.pdf
> 标签：#VLA #RT-2 #视觉语言模型 #动作即文本token #协同微调 #涌现能力 #思维链

## 一句话总结

RT-2 提出「视觉-语言-动作模型（VLA）」这一模型类别：把机器人动作编码成**文本 token**，与互联网规模的视觉问答（VQA）、图像描述等数据一起对预训练 VLM 做协同微调（co-fine-tuning），使同一个模型既能回答图文问题、又能输出低层机器人动作；其 55B 与 12B 两个实例在约 6000 次真机评测中把泛化成功率较 RT-1 提升约 2 倍，并涌现出符号理解（把物体放到数字"3"旁边）、语义推理（选最健康的饮料）、人物识别（移动到戴眼镜的人）以及链式思维（chain-of-thought）多级推理能力——「VLA」这一命名即来源于此。

## 1. 研究背景与动机

互联网规模的 VLM 已经具备开放词汇视觉识别、复杂图文推理等能力，这些能力对通用机器人极其诱人。但存在一个根本矛盾：机器人数据量（百万级轨迹）与网络数据量（十亿级 token/图像）差几个数量级，指望「暴力采集机器人数据」追平语义知识不现实；而现有把 LLM/VLM 用于机器人的方法（如 SayCan、PaLM-E）大多只充当**高层规划器/状态机**，把自然语言指令解析成原语（pick/place），再交给不含网络语义知识的独立低层控制器执行——低层控制阶段完全享受不到 VLM 的知识红利。

RT-2 要回答的问题是：**能否让预训练 VLM 直接充当低层机器人控制器**，从而把网络语义知识灌注进最底层的动作生成？关键的观察是：VLM 输出的是语言 token，如果我们把动作也变成「一种语言」，那么动作预测和图文问答就能统一在同一个输出空间里，模型权重完全共享、无需为动作新增任何专用模块。

论文强调这条路线「既简单又出奇地有效」（simple and surprisingly effective）：与 CLIPort 等需要 2D 动作空间、标定相机、为策略引入大量结构先验的方案不同，也与 Gato 等从零设计新架构的做法不同，RT-2 不新增任何参数、不改变模型骨架，只是**改写训练数据的输出格式**——把动作写成数字串，再沿用 VLM 本身的微调流程。这意味着 VLA 的进步可以直接「搭便车」于 VLM 社区的进步：更好的 VLM（更强的视觉理解、更多的预训练数据）理论上可以直接转化为更强的机器人策略，无需重造控制架构。

论文正式将这一类模型命名为 vision-language-action models（VLA）——「VLA」一词自此进入机器人学习的术语表，用于指代「以视觉-语言模型为底座、直接在输出空间生成机器人动作」的模型族。这个命名也隐含了一条技术路线宣言：机器人策略应当像 VLM 一样共享统一的预训练、统一的架构与统一的扩展规律，而不是每个任务重新设计一套专用系统。

## 2. 核心贡献

1. **VLA 概念与极简配方**：动作 = 文本 token，直接并入 VLM 训练集，用与自然语言 token 完全相同的方式处理；无需新增参数、不改架构，仅靠已有 VLM 的微调 API 即可完成。
2. **两个模型实例**：RT-2-PaLI-X（基于 PaLI-X 5B/55B）与 RT-2-PaLM-E（基于 PaLM-E 12B）；55B 版本是当时用于直接闭环控制的最大模型（比此前大一个数量级以上）。
3. **涌现能力评测**：首次定量评测 VLA 的符号理解、推理（数学、标识、营养、颜色、多语言）、人物识别三类涌现能力，最好模型较 RT-1 平均提升 3 倍以上。
4. **训练策略消融**：证明「从零训练 < 仅机器人数据微调 < 协同微调」，以及模型规模对泛化的正相关作用。
5. **链式思维推理**：只需几百步梯度微调加入 "Plan" 步骤，即可让 VLA 先做自然语言规划再输出动作，桥接 VQA 数据与操作数据。
6. **开源模拟基准验证**：在 Language-Table 模拟环境上，RT-2-PaLI-3B 达 90±10%，超过 LAVA（77±4）、RT-1（74±13）、BC-Zero（72±3）。

## 3. 方法详解

### 3.1 输入输出接口

- **输入**：一张（或多张）机器人相机图像 + 文本任务描述，按标准 VQA 格式组织："Q: what action should the robot take to [task instruction]? A:"。
- **输出**：一串代表动作的整数/文本 token，对应 7DoF 移动机械臂的 8 个动作分量：1 个终止（terminate）命令 + 6 自由度末端执行器位置/旋转增量 $\Delta pos_x, \Delta pos_y, \Delta pos_z, \Delta rot_x, \Delta rot_y, \Delta rot_z$ + 夹爪伸展量（gripper_extension）。动作字符串形如：

```
terminate Δpos_x Δpos_y Δpos_z Δrot_x Δrot_y Δrot_z gripper_extension
```

推理时把输出 token 反 tokenize（de-tokenize）成机器人动作，闭环执行。

### 3.2 动作表示为文本 token

- 沿用 RT-1 的离散化：除 terminate 外的每个连续维度均匀分为 **256 个桶**，动作因此表示为 8 个整数的序数。
- **关键工程问题**：如何把 256 个桶对应到 VLM 词表？两个实例处理方式不同：
  - **PaLI-X**：词表中 1000 以内的整数各自有唯一 token，直接复用整数的 token 即可；
  - **PaLM-E**：没有这种便利，于是**覆盖（overwrite）词表中 256 个最少使用的 token** 作为动作词表。论文指出这本质上是一种 symbol tuning，已有工作证明对 VLM 有效。
- **输出约束（output constraint）**：RT-2 必须在真实机器人上输出合法动作，因此在以机器人动作任务为提示时，解码只在合法动作 token 上采样；而在标准视觉-语言任务上模型仍可使用完整自然语言词表——统一模型、双模式解码。

这套动作编码的巧妙之处在于「零新增结构」：terminate 本身是一个普通词 token，8 个动作分量就是 8 个数字 token，机器人控制问题被完全还原为序列生成问题。代价是每个动作要自回归地解码 8 个 token，这对控制频率有直接拖累（见 3.6 节）；收益是模型可以复用所有为语言模型打造的推理基础设施（KV cache、采样策略等），并且动作与文本可以在同一段输出里交错出现——这正是 CoT 版本能先输出 "Plan" 再输出动作的机制基础。

### 3.3 协同微调（Co-Fine-Tuning）

这是全文最重要的训练配方：**不是**只用机器人数据微调 VLM（naïve fine-tuning），而是把机器人的轨迹数据与原始网络视觉-语言任务数据**混合**在同一个微调阶段训练。动机直白——让模型在微调期同时接触网络抽象视觉概念与低层动作，避免「灾难性遗忘」掉预训练概念。数据配比上（附录 B）：RT-2-PaLI-X 的机器人数据约占训练混合的 **50%**，RT-2-PaLM-E 约占 **66%**，通过提高机器人数据的采样权重来平衡每个 batch。虽然机器人数据占比高得惊人（相当于在混合训练里与海量网络数据「对等」甚至「更多」地出现），但消融证明这仍远优于纯机器人微调——关键在于**网络任务没有被移除**，概念遗忘由此被抑制。

在消融实验（4.3 节）中，协同微调在 5B 与 55B 两个尺寸上都优于「仅机器人微调」，论文将其解释为：微调阶段保留原始训练数据，模型不会遗忘 VLM 训练中获得的概念——这是在 LLM 微调中「指令微调导致能力退化」问题的机器人版本，RT-2 给出的解法是数据混合而非参数冻结。

### 3.4 训练目标

训练目标是标准的下一 token 预测（next-token prediction），对机器人数据而言即等价于机器人学习中的行为克隆损失。设动作 token 串为 $y = (y_1, \dots, y_K)$，输入图像为 $v$、指令为 $i$：

$$
\mathcal{L}(\theta) = -\,\mathbb{E}_{(v,i,y)\sim D}\left[\sum_{k=1}^{K} \log p_\theta(y_k \mid y_{<k}, v, i)\right]
$$

其中 $\theta$ 为 VLM 参数，$K$ 为动作 token 数（约 8 个），$D$ 为「机器人轨迹 + 网络图文任务」的混合数据集。公式按文中文字描述写出（论文原式在文本提取中有错乱），含义是：模型像生成文本一样自回归地生成动作串。

### 3.5 网络架构（继承自 VLM）

- **RT-2-PaLI-X**：ViT-22B 处理图像（每图切成 $k$ 个 patch，共 $n\times k$ 个 token），经投影层进入 32B 参数、50 层的 encoder-decoder（UL2 风格）骨干，自回归生成输出 token。
- **RT-2-PaLM-E-12B**：decoder-only 大语言模型，ViT-4B 把图像投影到语言嵌入空间；连续变量可直接拼接进文本输入，天然多模态。
- **Language-Table 用的 PaLI-3B**：ViT-G/14（2B）+ UL2-3B。

同时评测两种截然不同的架构，用意在于验证配方的通用性：PaLI-X 是 encoder-decoder（图像编码与文本解码分离），PaLM-E 是 decoder-only（把视觉投影进语言 token 空间、纯自回归）；两者共同点是**输出空间都是文本 token**——这正是动作 token 化能同时适配二者的根本原因。RT-2 不是一个为特定 VLM 定制的新架构，而是可套用到任意 $\{vision, text\} \to \{text\}$ 模型上的范式；这也解释了为何两个实例在泛化评测中平均表现相近（各有所长：PaLI-X 符号理解强、PaLM-E 数理推理强）。

### 3.6 实时推理

55B 模型无法在机器人工控机上运行，论文将其部署为**多 TPU 云服务**，机器人通过网络查询推理结果，同一服务可同时服务多台机器人。55B 版本可达 1–3 Hz 控制频率，5B 版本约 5 Hz。论文指出，这是**当时用于直接闭环机器人控制的最大模型，比此前大一个数量级以上**——这个「大一个数量级」既是 RT-2 的能力来源，也是其频率瓶颈的来源；「云端推理 + 网络传输」的模式后来被许多 VLA 部署方案沿用（OpenVLA 也提供了类似的远程推理服务器）。

### 3.7 链式思维（Chain-of-Thought）

借鉴 LLM 的 CoT 提示，只对 PaLM-E 版本做**几百步梯度**的微调，数据中加入一个 "Plan" 步骤：先用自然语言描述即将执行动作的目的，再输出动作 token，例如：

```
Instruction: I'm hungry. Plan: pick rxbar chocolate. Action: 1 128 124 136 121 158 111 255.
```

这种数据增强充当了 VQA 数据（视觉推理）与操作数据（生成动作）之间的桥梁，使模型能处理「我需要锤钉子，场景里哪个物体有用？→ Plan: Rocks」这类需要多级语义推理的指令。论文认为，这提供了 LLM/VLM 作为规划器（SayCan、PaLM-E 路线）与低层策略**合并进单一 VLA 模型**的初步证据：同一个模型无需外部规划器即可完成「理解意图 → 选择对象 → 生成动作」。

值得注意的是 CoT 微调成本极低——只对已训练好的 PaLM-E 版本再做几百步梯度更新即可触发该能力，说明模型内部本就具备被「引导」出来的推理潜力，CoT 数据的作用更接近解锁而非灌输。

## 4. 数据与训练设置

- **网络数据**：来自 PaLI-X / PaLM-E 原始预训练混合，主体是 WebLI 数据集——约 100 亿图文对、109 种语言，按跨模态相似度过滤取前 10%，约 10 亿训练样本；另含大量 captioning 与 VQA 数据。
- **机器人数据**：RT-1 的数据集——13 台机器人、17 个月、办公室厨房环境，每条演示带自然语言指令（7 类技能：Pick Object、Move Object Near Object、Place Object Upright、Knock Object Over、Open/Close Drawer、Place Object into Receptacle、Pick Object from Receptacle 等）。
- **训练超参（附录 E）**：
  - RT-2-PaLI-X-55B：学习率 1e-3，batch size 2048，协同微调 80K 梯度步；
  - RT-2-PaLI-X-5B：同学习率与 batch，270K 步；
  - RT-2-PaLM-E-12B：学习率 4e-4，batch 512，1M 步；
  - RT-2-PaLI-3B（Language-Table）：学习率 1e-3，batch 128，300K 步。均为下一 token 预测目标。
- **评测规模**：约 6000 条评测轨迹，采用 A/B 测试框架（同一条件下四个模型轮番评测）以降低方差。
- **基线设计（附录 C）**：所有基线使用完全相同的机器人数据，分别挑战方法的不同侧面——RT-1（35M）代表无 VLM 预训练的高性能策略；VC-1（ViT-L）与 R3M（ResNet50，用人类活动视频 Ego4D 学习表示）代表「预训练视觉表示 + 策略头」路线（语言条件用 USE 嵌入拼接实现）；MOO 代表「VLM 只作感知模块」路线（VLM 先在图像中标出目标物体像素，再由端到端策略操作）。四条基线覆盖了「无预训练」「表示学习预训练」「模块化 VLM」三种替代方案，使对比结论清晰指向「端到端 VLA」的独特价值。

## 5. 实验结果与关键消融

**总体泛化（Table 4，真机成功率 %）**：

| 模型 | 已见任务 | 未见物体(易/难) | 未见背景(易/难) | 未见环境(易/难) | 未见平均 |
|---|---|---|---|---|---|
| R3M | 45 | 32 / 14 | 13 / 9 | 0 / 2 | 12 |
| VC-1 | 63 | 34 / 10 | 13 / 3 | 0 / 0 | 10 |
| RT-1 | 92 | 31 / 43 | 71 / 9 | 26 / 14 | 32 |
| MOO | 75 | 58 / 48 | 38 / 41 | 19 / 3 | 35 |
| RT-2-PaLI-X-55B | 91 | 70 / 62 | 96 / 48 | 63 / 35 | **62** |
| RT-2-PaLM-E-12B | 93 | 84 / 76 | 75 / 71 | 36 / 33 | **62** |

已见任务上与 RT-1 相当（91/93 vs 92），但未见类平均 62%——约是次优基线（RT-1 与 MOO）的 **2 倍**，是 R3M/VC-1 的 **6 倍**左右。论文归因于 VLM 预训练迁移了更通用的视觉与语义概念。

**涌现能力定量（Table 5，成功率 %）**：RT-2-PaLI-X-55B 在符号理解上平均 82%（Symbol 1 达 93%）、推理平均 46%、人物识别平均 53%，总平均 60%；PaLM-E-12B 总平均 40%；RT-1 17%、VC-1 11%——最好版本比 RT-1 好 3 倍以上。趣味细节：数学推理上 PaLM-E（35%）反超 PaLI-X（25%），归因于 PaLM-E 预训练混合更偏语言/计算。

三类涌现能力的评测设计值得展开：**符号理解**直接检验 VLM 语义知识是否迁移——例如「move coke can near 3」「move apple to tree」「push coke can on top of heart」，这些数字、图标、图案从未出现在机器人数据中；**推理**包括视觉推理（「把苹果移到同色杯子旁」）、数学（「移到 2+1 的和旁边」「移到三乘二的答案旁边」）、多语言（西班牙语、德语、法语指令）与常识（「拿一份健康零食」「拿甜的饮料」）；**人物识别**包括名人照片（Taylor Swift、Tom Cruise、Snoop Dogg）与普通人属性（戴眼镜的人、白发男人、棕发女士）。每类指令说明中论文强调：所有这些交互在机器人数据中从未出现，提升只能来自视觉-语言预训练迁移。

论文还给出一条重要的免责注脚：PaLM-E-12B 的原始预训练混合中包含用于高层 VQA 规划任务的机器人图像（可能与其泛化评测场景相似），但这些训练样本**都不包含被评测的低层动作**，因此不构成对动作预测结果的直接泄漏。

**规模与训练策略消融（Table 6，未见类平均成功率 %）**：

| 模型 | 训练方式 | 平均 |
|---|---|---|
| PaLI-X 5B | 从零训练 | 9 |
| PaLI-X 5B | 仅机器人微调 | 42 |
| PaLI-X 5B | 协同微调 | 44 |
| PaLI-X 55B | 仅机器人微调 | 52 |
| PaLI-X 55B | 协同微调 | **63** |

结论：从零训练大模型性能极差（5B 仅 9%，因此放弃 55B 从零训练）；协同微调 > 仅机器人微调 > 从零训练；模型越大泛化越好。

**Language-Table 模拟（Table 1）**：RT-2-PaLI-3B 90±10% vs LAVA 77±4%、RT-1 74±13%、BC-Zero 72±3%，说明该配方在仿真与其他机器人上也有效。实验细节：模型在小尺寸 PaLI 3B 上协同微调了多种预测任务——给定两帧图像与指令预测动作、给定图像预测指令、预测机械臂位置、预测两帧间时间步数、判断任务是否成功；其中动作被离散为文本 "X Y"，X、Y 取值于 {-10,…,+9,+10} 表示末端执行器的 2D 笛卡尔增量。由于模型较小，推理速度与基线同为 5Hz，说明「动作=文本」不必以巨大模型为前提。

综合来看，RT-2 的评测体系回答了两个层次的问题：**能力层**——VLM 语义知识能否迁移到低层控制（Table 4/5 给出肯定证据）；**配方层**——效果来自规模还是训练策略（Table 6 证明预训练权重的存在与协同微调缺一不可，从零训练的大模型几乎不会泛化）。这套「拆解到根因」的消融设计，是 RT-2 被称为里程碑的重要原因。

**链式思维（定性）**：能完成「把与众不同的物体捡起来（Plan: pick rxbar chocolate）」「把绿色物体放到一起」「我困了，给我拿杯喝的（Plan: pick redbull can）」等需要多级推理的任务。

## 6. 局限性

1. **物理技能边界不变**：网络预训练带来的是语义/视觉概念迁移，模型不能凭此获得机器人数据中不存在的新动作——技能分布仍受限于机器人数据，只是旧技能能以新方式组合使用。
2. **计算成本高**：55B 模型 1–3 Hz、依赖云端 TPU 服务，对需要高频控制的场景，实时推理会成为主要瓶颈；量化、蒸馏是未来方向。
3. **可用 VLM 稀缺**：当时能用于构建 VLA 的开放 VLM 很少；开源模型的涌现与专有模型开放微调 API 是社区繁荣的前提。
4. **具体失败模式（附录 G）**：按指定部位（如把手）抓取差；无法完成未见过的新运动（擦桌子、使用工具）；灵巧精细动作（叠毛巾）失败；需要多层间接推理的任务失败；对未见物体动力学（推笔、推香蕉）泛化差。
5. **部署与安全的隐性依赖**：机器人在线依赖云端 TPU 服务，链路中断即失去控制能力；输出约束机制保证动作合法性，但也意味着给模型的提示一旦被判定为「机器人动作任务」，它就只能在动作 token 中采样、无法输出"拒绝执行"之类的自然语言——这类系统级安全边界在论文中未被展开，是走向实际部署前必须补课的部分（此条为基于论文描述的工程视角补充，非原文结论）。

## 7. 对无人机端到端导航的启示

**（1）观测接口**。RT-2 的标准接口是「单图/多图 + 文本 VQA 问题」，这对无人机是天然利好：机载相机帧可以像机器人相机一样进 VLM，而「任务=自然语言」意味着无人机可以直接接受「飞到足球场上空悬停」「跟着穿红衣服的人」这类指令，无需专门的动作标签体系。RT-2 涌现能力的具体类别几乎都能在无人机任务中找到对应物：符号理解对应「飞到 3 号楼」「绕到 H 停机坪」；推理对应「飞到视野中最高的建筑旁」「跟随那条最堵的路」；人物识别对应「在人群中找到穿黄马甲的人并跟随」。但注意 RT-2 未使用 IMU、历史帧与本体状态——无人机高速运动下单帧无法判断速度，这与 OpenVLA 一节所说的局限相同，需要自行扩展输入通道（多帧、IMU 文本化或投影进语言空间）。

**（2）动作表示**。RT-2 把连续控制量按 256 桶离散化后嵌入语言词表，这个「所有模态统一到 token 空间」的思想对无人机同样成立：例如把速度指令 $(v_x, v_y, v_z, \omega_{yaw})$ 分桶成 token，即可让一个 VLM 同时做任务规划与飞行控制。更值得借鉴的是**动作与文本可混合输出**这一性质：无人机可以输出「接近目标 → 悬停扫描 → 降落」这类 Plan token 后再接控制 token，把任务分解与底层控制统一在一个自回归序列里。但离散化粒度与自回归解码延迟（8 个 token 顺序生成）对高频飞控是硬伤；更现实的路线是离散语义 token + 独立高频底层控制器，或动作分块一次预测多步动作以减少解码频率。

**（3）控制频率**。55B 模型 1–3 Hz 的教训非常直接：模型规模与频率强耦合。无人机悬停/航点飞行惯性大、容错尚可，但穿越机竞速（RaceVLA 类任务）需要远超 RT-2 的频率。RT-2 给的工程解法是「云端多 TPU 服务 + 网络查询」，但无线链路延迟和丢包对飞控是安全隐患，机载小模型（5B 级 + 量化/固化）或远端推理+本地兜底控制是更可行的组合。另一个可借鉴点：5B 模型可以有 5Hz，3B 保持 5Hz 与模拟基线持平——说明**缩小底座换取频率**是 VLA 部署的常规权衡，无人机场景应优先选小底座 + 领域微调，而不是追求最大参数模型。

**（4）sim-to-real 迁移**。RT-2 的核心配方「协同微调：网络预训练数据 + 领域数据的混合」对无人机可以整体平移：用互联网视频/图像预训练的 VLM 做底座，混合无人机仿真数据与真机数据协同微调，从而保留语义先验又接地到飞行动作。消融给出的两条铁律同样适用：其一，从零训练不行，预训练权重是语义泛化的必要条件；其二，只混少量网络数据即可显著缓解遗忘，因此仿真-真机域的混合比例不必照搬 50%，但一定要让模型在微调期持续「见到」预训练分布。它用「Plan 中间层」桥接推理数据与动作数据的思想，也可以用于无人机长程导航任务分解（先输出航点计划文本，再输出控制 token），并缓解纯端到端策略样本效率低的问题。
