# Octo：开源通用机器人策略（Octo: An Open-Source Generalist Robot Policy）解读

> 论文：Octo: An Open-Source Generalist Robot Policy（UC Berkeley / Stanford / CMU / Google DeepMind，arXiv 技术报告 2024）
> arXiv：2405.12213｜PDF：papers/05_Octo_2405.12213.pdf
> 标签：#通用机器人策略 #开源 #跨本体 #扩散动作头 #Transformer #高效微调

## 一句话总结

Octo 是首个完全开源的通用机器人策略（Generalist Robot Policy）：在 Open X-Embodiment（OXE）的 800k 条轨迹上训练的「Transformer 主干 + 轻量扩散动作头」，通过模块化的 token 接口同时支持语言指令与目标图像、任意相机组合与观测历史，并能在消费级 GPU 上于数小时内微调到新的观测空间、动作空间乃至新本体。

## 1. 研究背景与动机

机器人学习的常规做法是为每台机器人、每个任务单独采集数据、从零训练策略，数据成本高且泛化狭窄。语言与视觉领域已证明「大规模预训练 + 下游微调」的有效性，但构造通用的机器人基础模型面临独特困难：不同本体的传感器配置、动作空间、任务描述方式、环境都不一致。

此前已有的通用机器人策略（论文统称 GRP，Generalist Robot Policy）如 RT-1-X、RT-2-X、RoboCat、GNM 等虽已展现跨机器人能力，但论文指出三个共同缺陷：

1. **观测接口僵化**：下游用户被迫使用预训练时固定的输入组合（例如只支持单一第三人称相机），增删传感器往往需要重训大块模型；
2. **微调能力差**：难以适配新观测空间、新动作空间；
3. **不开放**：最大规模的模型都是闭源的，社区无法复现或推进。

Octo 的目标就是为「广泛适用、开源可复现」的通用策略打地基：既要在预训练数据分布内开箱即用地控制多种机器人，又要能以很小的代价被改造到全新机器人配置上。

## 2. 核心贡献

- **Octo 模型**：在 OXE 中精选的 25 个数据集、800k 条轨迹（论文称为当时最大的机器人操作演示数据集）上训练的 transformer 策略，参数量 27M（Octo-Small）与 93M（Octo-Base）两档；OXE 全量约 1.5M episodes 中筛选出这 800k，而 RT-X 模型只用了 350K。
- **首个可高效微调到新观测/动作空间的 GRP**：新增力/力矩输入、关节位置控制动作、新机器人本体都只增加少量新参数，保留全部预训练权重。
- **灵活的接口**：语言或目标图像作任务条件；接受多个相机（第三人称 + 手腕）、观测历史；输出多模态、分块（chunked）的连续动作。
- **完全开源**：预训练 checkpoint、JAX 训练/微调代码、OXE 数据加载器全部公开（https://octo-models.github.io）。
- **系统消融**：架构（ViT vs ResNet）、数据混合（25 数据集 vs RT-X 的 11 数据集 vs 单机器人）、训练目标（扩散 vs MSE vs 离散化）、模型规模四类设计决策的定量比较。

## 3. 方法详解

### 3.1 输入输出接口

核心是一个 transformer 策略 π，三段式：输入 tokenizers（把任务与观测变成 token）→ transformer 主干（产出嵌入）→ readout heads（输出动作）。

- **任务**：语言指令 ℓ 或目标图像 g（二选一，也可以同时提供）；
- **观测**：长度为 H 的观测序列（论文用 2 帧历史），每帧含相机图像；
- **输出**：一个动作块（chunk），即若干连续动作。

### 3.2 Tokenization 设计

- **语言**：用预训练 t5-base（111M）编码，输出 16 个语言嵌入 token；消融发现冻结的 base 编码器效果最好（更大的 386M 版本或微调末两层都没有提升，论文归因于数据集的自由文本语言标注不够丰富）。
- **图像**：浅层卷积栈 + 展平为 16×16 的 patch 序列（ViT 式）。第三人称 256×256 图像 → 256 个 token，手腕 128×128 图像 → 64 个 token。刻意选择「浅 CNN + 大 transformer」的 transformer-first 结构：消融显示在 800k 大数据上，ResNet 式编码器显著不如 ViT 式结构（后者只有在小数据从零训练时占优）。
- 任务与观测 token 加可学习位置嵌入 p，拼接为统一序列。

### 3.3 注意力结构与 readout token

- 观测 token 只能因果地（causally）访问同一时间步或更早的观测 token 以及任务 token；不存在的观测（例如没有语言标注的数据集）整块掩码。
- 序列中额外插入**可学习的 readout token**（类似 BERT 的 [CLS]）：它 attend 前面的观测与任务 token，但**不被任何 token attend**——只被动读、不影响其它 token 的内部表示。动作头就作用于 readout token 的嵌入上。
- 这种块状注意力 + 被动 readout 的设计让「增删输入输出」变成在序列上插 token、在输出侧换头：微调时只需新增位置嵌入、新的轻量编码器、或新的动作头参数，其余预训练权重原样保留。这是 Octo 相对 RT-1-X 等模型的核心灵活性来源：后者的输入输出被主干结构「锁死」，改任务规格要重新初始化大块模型。

### 3.4 扩散动作头（核心公式）

条件扩散解码头建模连续、多峰的动作分布。关键效率设计：**每个动作预测只做一次 transformer 主干前向**，多步去噪完全在小型动作头里进行。动作头是 3 层 MLP（隐层 256、残差连接、LayerNorm），用标准 DDPM 目标、余弦噪声调度、20 个扩散步训练。

生成动作时，从高斯噪声 x_K ~ N(0, I) 出发，执行 K 步去噪，每步为：

$$
x_{k-1} = \alpha\left(x_k - \gamma\, \epsilon_\theta(x_k, e, k) + \mathcal{N}(0, \sigma^2 I)\right)
$$

逐符号解释：x_k 是第 k 步的含噪动作；ε_θ(x_k, e, k) 是去噪网络，条件于上一步结果 x_k、步索引 k 和 transformer 动作 readout 的输出嵌入 e；α、γ、σ 构成噪声调度（论文用标准余弦调度）；N(0, σ²I) 注入随机性以表达多峰分布。训练时，对数据集动作加高斯噪声构造 x_k，网络回归原始动作（即预测所加的噪声）。

**为什么用扩散头而不是更简单的头**（这是论文消融明确的结论）：

- MSE 回归头：会训练出「对冲」策略（hedging）——面对多峰数据时输出平均，表现为动作缓慢、手腕不旋转；
- 离散化动作头（每维 256 桶 + 交叉熵，如 RT-1）：动作更「果断」但精度不足，经常抓取失败；
- 扩散头兼顾连续精度与多峰表达，在同一评估基线上远优于两者（见第 5 节）。

### 3.5 训练数据与权重

从 OXE 梳理 25 个数据集（图 3 列出 Fractal、Kuka、Bridge 各占约 17% 等采样权重）。筛选背后的逻辑是：数据质量与多样性直接决定策略质量。具体规则：剔除无图像流的数据（无法训练视觉策略）、非 delta 末端执行器控制的数据（动作空间难以统一）、过于重复或低分辨率的数据（学不到新行为）、过分小众的数据；余下数据集人工划分为「更多样」与「较少样」两类，前者采样权重加倍，个别重复性高的数据集降权——等于人为把采样分布拉向多样性。对齐处理：

- 缺失相机通道补零；
- 夹爪动作空间对齐为 +1 = 张开、0 = 闭合（绝对表示，论文试过相对表示，虽然抓取成功率略高但失败后重试行为更少，最终选绝对表示）；
- 用 hindsight goal relabeling 自动生成目标图像（从未来轨迹中均匀选一个状态作为目标图）；
- 训练时随机把语言指令或目标图置空，使模型能分别以两种模式条件化；无语言标注的数据集一律用目标图条件化，这样大部分监督信号来自自监督的视觉观测，降低对语言标注的依赖。

### 3.6 微调机制

微调时更新全模型（消融显示优于冻结部分参数），并沿用同一套超参数：给定约 100 条目标域轨迹，微调 50k 步，余弦衰减学习率 + 线性 warmup。新观测（力/力矩）只需加一个小的新编码器；新动作空间（如关节位置控制、ALOHA 的 14 维动作）只需初始化一个新的动作头——主干完全复用。

## 4. 数据与训练设置

- **数据**：OXE 25 个数据集、800k 条轨迹（含各种单臂机器人与演示质量）；观察到的大多数数据集动作频率在 5~15Hz 量级（例如 CMU Baking 15Hz、Berkeley Peg 5Hz、多数 10Hz）。
- **优化**：AdamW，学习率 3e-4，逆平方根衰减 + 2000 步 linear warmup，权重衰减 0.1，梯度裁剪 1.0，batch size 2048；两个模型都训练 300k 步。ViT-B 规模模型（Octo-Base）在 TPU v4-128 pod 上约 14 小时完成。
- **架构规格**：Octo-Small 12 层、隐宽 384、MLP 1536、6 头、27M 参数；Octo-Base 12 层、隐宽 768、MLP 3072、12 头、93M 参数；消融还用到了 10M 的 Octo-Tiny。
- **观测历史**：2 帧（消融发现再增加历史长度收益递减）。
- **微调开销**：单张 NVIDIA A5000（24GB）约 5 小时，多卡可加速；对所有 6 个微调任务使用完全相同超参数——「同一配方通用」本身就是论文想验证的卖点。
- **训练工程细节（附录）**：跨 25 个数据集混洗是难点，用最多 500k 的 shuffle buffer，每条轨迹随机最多抽 100 步，避免长 episode 挤占；patch 16×16（比 32×32 明显更好，代价是 4 倍 token 数）；图像做随机裁剪 + 颜色抖动等增强。

## 5. 实验结果与关键消融

**对比设置**：开箱即用比较对象是 RT-1-X（同用 OXE 预训练、35M 参数，公开可得的最强基线）与 RT-2-X（55B、闭源）；微调比较对象是「从零训练的 ResNet+Transformer」（约 28M，接近 RT-1 的规模）与 VC-1 预训练视觉表示的 MLP 动作头。评测横跨任务多样性（WidowX BridgeV2 换物体）、长时域（Stanford Coffee 抓取并精确放入咖啡机）与精细接触操作（Berkeley Insertion 间隙仅 1.5mm），微调域每个用约 100 条演示、20 次试验、且全部共用同一套微调超参。

**开箱即用（zero-shot）多机器人控制**：在 9 个真实机器人平台、4 家机构的评测中（WidowX BridgeV2、UR5 Tabletop、RT-1 Robot 等），平均成功率比公开可得的最强通用策略 **RT-1-X（35M）高 29%**；在 WidowX 与 RT-1 Robot 上与 **RT-2-X（55B 参数）表现相当**——参数量差约 590 倍。此外，用目标图像条件化（而非语言）在 WidowX 任务上成功率再高 **25%**，论文解释为目标图像提供了更多「如何完成」的信息。

**零样本泛化分解**（WidowX，20 次试验/任务）：分布内平均 85%、新物体平均 80%、新环境平均 40%、**新技能仅 5%**（翻杯子 10%、插块入槽 0%）——说明 Octo 的零样本能力主要覆盖已知技能，新技能必须靠微调。

**高效微调**（6 个任务，各约 100 条演示、各 20 次试验）：Octo 平均成功率 **72%**（Berkeley Insertion 70%、Stanford Coffee 75%、CMU Baking 50%、Berkeley Pick-Up 60%、Berkeley Coke 100%、Berkeley Bimanual 80%），从零训练的 ResNet+Transformer 基线 20%、预训练视觉表示 VC-1 15%；Octo **比次优基线高 52%**。其中 Berkeley Insertion 使用了新观测（力/力矩），Pick-Up 与 Bimanual 使用新动作空间（关节位置），Coke 与 Bimanual 是新机器人本体——证明微调机制对新接口有效。

**消融**（WidowX，40 次试验/平均）：

| 消融项 | 平均成功率 |
|---|---|
| Octo-Small（完整） | 83% |
| 换成 RT-X 的 11 数据集混合 | 60% |
| 只用单机器人数据（Bridge） | 43% |
| 离散化动作预测（类似 RT-1） | 18% |
| 连续动作 MSE 预测 | 35% |
| ResNet-50 + Transformer 架构 | 70% |

- **数据**：数据混合越宽越好——单一机器人数据仅 43%，换成更大的 OXE 混合后大幅提升；
- **目标**：扩散头（83%）显著优于 MSE（35%）与离散化（18%），印证第 3.4 节的机制分析；
- **架构**：ViT 式 transformer-first 优于 ResNet-50 融合架构，但论文也承认 ResNet 在小数据从零训练时更好；
- **规模**：从 10M（Tiny）到 27M（Small）到 93M（Base）零样本成功率单调提升，Base 对初始场景配置更鲁棒、更少提前抓取；
- **附加经验**：2 帧历史、动作分块、16×16 patch 均有效；反向经验包括「微调语言编码器无益」、「输入本体状态反而更差」（论文怀疑是状态与未来动作强相关导致的因果混淆）。

## 6. 局限性

- **手腕相机处理不足**：只有 27% 的预训练数据含手腕相机信息，微调时常常只用第三人称相机的效果更好；
- **语言条件偏弱**：只有 56% 的预训练数据带语言标注，语言条件化与目标图像条件化之间存在明显性能差距；
- **只学最优演示**：OXE 全是成功轨迹，无法利用次优数据或在线交互（需要换用其它学习目标）；
- **范围限于单双臂操作**：作者明确表示扩展到导航与移动操作机器人是「高机会方向」但未做；
- 长时域和动态任务能力有限，评测中大部分任务为短/中时域 picking/placing。

## 7. 对无人机端到端导航的启示

- **观测接口**：Octo 的「任务 token + 任意相机 token + readout token」结构对无人机非常友好——增删机载相机、加入 IMU/高度计等新传感器只需加新编码器与位置嵌入，不动主干；这是比固定输入接口的 RT-1-X 路线更适合「每台无人机传感器配置都不一样」的工程现实。手腕相机处理差与语言条件弱两个缺陷提醒：数据里出现过的模态才可靠，若要用语言指令驱动飞行，语言标注比例必须提上去。
- **动作表示**：扩散动作头 + 动作块 + receding horizon 的组合与 Diffusion Policy 一脉相承，天然支持连续动作（推力、角速度、速度指令）与多峰分布（绕障走左/走右）；论文引用的 NOMAD（目标掩码扩散导航策略）已证明扩散策略可直接用于导航任务，把末端执行器的 delta 动作空间替换为无人机的速度/位置增量是一条可直接尝试的路径。此外「每个控制周期只跑一次主干、去噪全在小头里」的算力分配方式很适合机载部署。
- **控制频率**：Octo 评测的场景多为 5~15Hz 的末端 delta 控制，扩散头 20 步去噪的推理开销在 A5000 上亦可微调训练。对需要 ≥50Hz 的无人机控制，直接照搬存在风险：可参考「策略低频输出动作块 + 底层控制器高频跟踪」的分层（论文自身也用底层控制器执行 5Hz 策略的输出），或改用 π0 式少步流匹配缩减去噪步数。
- **sim-to-real 迁移**：Octo 的微调协议是极佳模板——约 100 条目标域演示、统一超参、单卡 5 小时即可把通用策略迁到新本体，这意味着无人机可以先用海量异构数据（含仿真）预训练，再用少量真机飞行数据微调。特别是它「新动作空间 = 换一个动作头」的机制，允许预训练策略零成本迁移到不同无人机机型（多旋翼/固定翼动作维度不同也一样）。同时要注意其教训：本体状态等强相关输入可能引发因果混淆，观测设计要谨慎。
