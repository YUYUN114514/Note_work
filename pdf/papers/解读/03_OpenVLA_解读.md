# OpenVLA：开源视觉-语言-动作模型（OpenVLA: An Open-Source Vision-Language-Action Model）解读

> 论文：OpenVLA: An Open-Source Vision-Language-Action Model（CoRL 2024 Oral；本 PDF 为 arXiv 预印本 v3）
> arXiv：2406.09246｜PDF：papers/03_OpenVLA_2406.09246.pdf
> 标签：#VLA #OpenVLA #开源机器人策略 #OpenX #LoRA #量化推理 #模仿学习

## 一句话总结

OpenVLA 是一个 7B 参数、完全开源（代码、权重、训练管线）的视觉-语言-动作模型：以 Prismatic-7B VLM（DINOv2 与 SigLIP 融合视觉编码器 + Llama 2 7B）为底座，在包含 970k 条真实机器人轨迹的 Open X-Embodiment（OpenX）数据集上微调，把末端执行器 7 维连续动作按分位数离散成 256 桶、词表末尾 256 个 token 作动作词；它在 29 个评测任务上以 7 倍更小的参数量超过闭源 55B 模型 RT-2-X 16.5 个百分点，并首次系统给出 VLA 的高效微调（LoRA）、量化部署（int4）与数据整理最佳实践。

## 1. 研究背景与动机

机器人操作策略最大的弱点是泛化：传统模仿学习策略能适应物体位置、光照等初始条件变化，但对场景干扰物、新物体、新指令束手无策。视觉与语言领域的基础模型（CLIP、SigLIP、Llama 2）具备这些泛化能力，其预训练数据规模（万亿 token 级）与机器人数据（100K–1M 条）差 4 个数量级以上，巨大落差提示了一条捷径：**把互联网预训练的视觉-语言模型当作机器人策略的核心构件**。

RT-2 已经验证了 VLA 的威力，但存在两个阻碍普及的痛点：其一，现有 VLA（RT-2、RT-2-X、RFM-1、Lingo-2 等）几乎全部**闭源**，架构、训练过程、数据配比对社区不可见；其二，已有工作没有回答「如何把 VLA 高效微调到新机器人/新任务」这一落地的关键问题，尤其是在消费级 GPU 等廉价硬件上。开源侧当时最强的通用策略 Octo 虽支持多机器人、可微调，但它由预训练组件 + 从头训练的新模块「拼装」而成，泛化与语言定位能力与 VLA 有明显差距。机器人领域需要一个像开源 LLM 生态（Llama、Mistral 等）那样的开放 VLA 基础设施。

OpenVLA 的判断是：要建立这样的生态，一个模型不够，必须同时交付**模型、数据管线、微调与部署工具链**，让社区能在同一基线上迭代训练策略、数据配比与推理优化，而不是各自从零复现闭源系统。

## 2. 核心贡献

1. **OpenVLA 模型**：7B 参数开源 VLA，在 OpenX 的 970k 条机器人演示上训练，跨本体开箱即用，刷新通用操作策略的 SOTA（在 BridgeData V2 与 Google Robot 两类本体、29 个任务上平均超过 RT-2-X 16.5% 的绝对成功率）。
2. **高效微调方法论**：首次系统研究 VLA 微调——全量微调、仅最后一层、冻结视觉编码器、sandwich 微调、LoRA——并证明 LoRA（r=32）以 1.4% 的可训练参数达到与全量微调相当的性能，训练算力降低 8 倍。
3. **量化部署**：int4 量化在不损失下游成功率的前提下把推理显存减半（16.8GB→7.0GB），并揭示「推理速度会改变系统动力学」这一被忽视的部署陷阱。
4. **完全开源**：发布模型 checkpoint、微调 notebook 与支持 OpenX 大规模训练的 PyTorch 代码库（AMP、FlashAttention、FSDP、HuggingFace 集成）。
5. **关键设计决策消融**：VLM 骨干选择（Prismatic vs LLaVA vs IDEFICS）、分辨率（224 vs 384）、视觉编码器微调与否、训练轮数、OpenX 数据与双视觉编码器的作用等。
6. **仿真可复现适配**：在 LIBERO 仿真基准上跑通微调并开源复现材料，并公开了一批对社区有普遍价值的数据清洗经验（见 5 节）。

## 3. 方法详解

### 3.1 输入输出接口

- **输入**：单张第三人称相机图像（224×224）+ 自然语言任务指令（提示模板："What should the robot do to {task}? A:"）。
- **输出**：7 维机器人控制动作（末端执行器 $\Delta x, \Delta \theta, \Delta Grip$），即位置增量、旋转增量与夹爪开合；经反 tokenize 后闭环执行，单步动作、不做动作分块（action chunking）。

### 3.2 模型结构：Prismatic VLM + 动作 token

三段式结构（Fig. 2）：

1. **视觉编码器（约 600M 参数）**：SigLIP 与 DINOv2 两个预训练编码器对同一图像 patch **分别编码、通道维拼接**（fused vision backbone）。DINOv2 提供低层空间细节、SigLIP 提供高层语义——论文认为后者常用但空间推理不足，而对控制任务空间精度至关重要。
2. **投影器**：2 层 MLP，把视觉特征投到语言模型嵌入空间。
3. **LLM 主干**：Llama 2 7B，自回归生成输出 token（可能是自然语言回答，也可能是动作 token）。

这正是 Prismatic-7B VLM 的架构；Prismatic 本身在 LLaVA-1.5 数据混合（约 1M 图文/纯文本样本）上微调过。OpenVLA 在此 VLM 之上继续微调，让输出空间包含机器人动作。

推理时，模型对动作任务的回复是一段数字串 token，需要先把 token 反查回整数（反 tokenize），再按各动作维度的分位数统计**反归一化**回物理量，交给机器人控制器执行。整个流程与语言生成完全同构，无需任何专属解码器或动作头——这也是 OpenVLA 代码量小、易于集成的原因。

### 3.3 动作表示：分位数离散化 + 词表覆盖

- 每个动作维度**独立离散为 256 桶**，动作变为 7 个 $[0..255]$ 的整数（N 维动作 → N 个整数）。
- 与 RT-1 的关键区别：桶宽不用 min-max 边界划分，而是均匀划分训练数据动作的 **1%–99% 分位数区间**——这样可以忽略离群动作（outlier），避免个别异常值把离散化区间撑大、降低有效分辨率。
- Llama tokenizer 只预留了 100 个 special token，不够 256 个动作 token，于是沿用 RT-2/PaLM-E 的做法：**覆盖词表中最少使用的 256 个 token**（即词表最后 256 个）作为动作词表。

### 3.4 训练目标

下一 token 预测（next-token prediction），**仅在动作 token 上计算交叉熵损失**。设第 $n$ 个动作的 token 序列为 $y=(y_1,\dots,y_N)$，输入图像为 $v$、指令为 $i$：

$$
\mathcal{L}(\theta) = -\,\mathbb{E}_{(v,i,y)\sim D}\left[\sum_{j=1}^{N} \log p_\theta(y_j \mid y_{<j}, v, i)\right]
$$

其中 $\theta$ 为模型参数，$D$ 为 OpenX 机器人演示数据集，$N$ 为动作维度数（7）。公式按论文文字描述整理（原文未展开该式），含义即：像生成文本一样逐 token 生成动作，只在动作位置上回传梯度。

### 3.5 关键设计决策（正文 3.4 节的经验总结）

- **VLM 骨干**：在 BridgeData V2 上的小规模对比中，LLaVA 比 IDEFICS-1 在语言定位（多物体场景中操作指令指定物体）任务上绝对成功率**高 35%**；Prismatic 又在简单任务与语言定位任务上比 LLaVA **再高约 10%**——归功于 SigLIP-DINOv2 融合骨干带来的空间推理能力，且 Prismatic 代码模块化易用。
- **图像分辨率**：224×224 与 384×384 性能无差异，但后者训练慢 3 倍——最终选 224（注意这与 VLM 基准上"分辨率越高越好"的结论相反）。
- **视觉编码器必须微调**：VLM 文献普遍主张冻结视觉编码器（保护预训练特征），但 VLA 训练中**冻结会导致性能显著变差**——论文推测预训练视觉骨干缺少精确控制所需的细粒度空间细节；实测对比中冻结视觉平均成功率 46.7%，微调后 80.0%。
- **训练轮数**：LLM/VLM 通常 1–2 个 epoch，但 VLA 需要反复迭代数据，真机性能直到**动作 token 准确率超过 95%** 才停止上升；最终训练跑了 **27 个 epoch**。
- **学习率**：扫参后固定为 2e-5（与 VLM 预训练一致），未发现 warmup 有增益。

### 3.6 训练与推理基础设施

- **训练**：64 张 A100、14 天，共约 **21,500 A100 小时**，batch size 2048。
- **推理**：bfloat16 加载占 15GB 显存，单张 RTX 4090 上约 **6Hz**（无编译、无投机解码等加速技巧）；提供远程推理服务器方案，便于算力不在机器人本地的场景。
- **量化**：int4 推理显存 7.0GB、吞吐高于 bf16，成功率与 bf16 相当（非阻塞控制下 71.9% vs 71.3%）；int8 因反量化算子开销反而更慢。

### 3.7 数据整理（OpenX）

以 OpenX（70+ 数据集、200 万+ 轨迹）为基础，做两步整理：**统一输入输出空间**——只保留至少有一个第三人称相机、单臂末端执行器控制的操作数据集；**均衡混合**——采用 Octo 的启发式混合权重（多样性差的数据集降权/剔除，任务与场景丰富的数据集升权）。曾尝试加入 DROID 数据集（保守权重 10%），但其动作 token 准确率全程偏低，最终训练后三分之一阶段将其移除并重新分配权重。训练混合的主要成分：Fractal 12.7%、Kuka 12.7%、Bridge 13.3%、BC-Z 7.5%、FMB 7.1%、Language Table 4.4%、DROID 10%（仅前 2/3 阶段）等。

## 4. 数据与训练设置小结

- 训练数据：970k 条机器人轨迹（从 OpenX 筛选），跨多种机器人本体、场景与任务。
- 训练：64×A100×14 天；固定学习率 2e-5；batch 2048；27 epochs；与 VLM 预训练一致的超参。
- 评测：BridgeData V2 WidowX 17 任务×10 次 = 170 rollouts/方法；Google Robot 12 任务×5 次 = 60 rollouts/方法；Franka-Tabletop 6 任务与 Franka-DROID 1 任务（每个任务 10–150 条演示）；LIBERO 仿真 4 个任务套件（每套 500 trials × 3 seeds）。

## 5. 实验结果与关键消融

**直接评测（开箱即用，跨本体）**：

| 评测 | OpenVLA (7B) | RT-2-X (55B) | Octo (93M) | RT-1-X (35M) |
|---|---|---|---|---|
| BridgeData V2 平均（170 rollouts） | **70.6±3.2%** | 50.6±3.5% | 20.0±2.6% | 18.5±2.7% |
| Google Robot 平均（60 rollouts） | **85.0±4.6%** | 78.3±5.4% | 26.7±5.8% | 33.3±6.1% |

评测任务按泛化轴精心设计：BridgeData V2 的 17 个任务覆盖视觉泛化（5 个：新背景/干扰物/颜色外观）、运动泛化（2 个：新物体位置与朝向）、物理泛化（3 个：新大小与形状）、语义泛化（4 个：新目标物体/概念）与语言定位（3 个：多物体场景中按指令操纵正确目标）；Google Robot 的 12 个任务中 5 个为训练分布内、7 个为分布外（新背景、新物体、新关系指令如「把苹果放到盘子上（训练只见过移到盘子旁）」、「把可乐移到 Taylor Swift 的照片旁」）。所有评测都用 A/B 方式固定初始状态。

摘要口径：跨 29 个任务平均比 RT-2-X **高 16.5% 绝对成功率，参数少 7 倍**。语言定位（多物体场景操纵指令指定物体）显著更强。唯一输给 RT-2-X 的是语义泛化（未见过物体/指令/网络概念），论文归因于 RT-2-X 用网络数据+动作数据协同微调、保留了更多预训练知识，而 OpenVLA 只用了机器人数据微调；同时 OpenVLA 训练数据更大（970k vs RT-2-X 350k）、清洗更细（如过滤 Bridge 数据的全零动作）、视觉骨干更好。一个著名的工程发现：BridgeData V2 每条演示首步是全零动作，RT-2-X 未清洗因而常在评测中"冻住"，双方评测时采用「查询第二可能动作」的规避方案。

**高效微调（新机器人设置）**：

| 方法 | Franka-Tabletop 平均 | Franka-DROID 平均 |
|---|---|---|
| Diffusion Policy（从零训练） | 48.5±4.9% | 35.0±8.0% |
| Octo（微调） | 43.4±4.4% | 38.3±8.5% |
| OpenVLA (scratch)（不加载 OpenX 权重） | 43.4±4.6% | 21.7±6.6% |
| **OpenVLA（微调）** | **67.2±4.0%** | **58.3±7.2%** |

Diffusion Policy 在单指令窄任务（如"把胡萝卜放进碗里"）上更强，但在多物体、多指令、需语言定位的任务上明显落后；OpenVLA 是唯一在所有任务上至少 50% 成功率的方法，摘要口径比从零训练的 Diffusion Policy **高 20.4%**。

**参数高效微调（Table 1，Franka-Tabletop 子集）**：

| 策略 | 成功率 | 可训练参数 | 显存(batch16) |
|---|---|---|---|
| 全量微调 | 69.7±7.2% | 7,188.1M | 163.3GB |
| 仅最后一层 | 30.3±6.1% | 465.1M | 51.4GB |
| 冻结视觉 | 47.0±6.9% | 6,760.4M | 156.2GB |
| Sandwich | 62.1±7.9% | 914.2M | 64.0GB |
| LoRA r=32 | 68.2±7.5% | 97.6M（1.4%） | 59.7GB |
| LoRA r=64 | 68.2±7.8% | 195.2M | 60.5GB |

LoRA 以 1.4% 参数匹配全量微调，单张 A100 上 10–15 小时即可微调新任务（**8 倍算力节省**）；LoRA rank 影响可忽略，推荐 r=32。

**量化推理（非阻塞控制）**：bf16 71.3±4.8%（16.8GB）、int8 58.1±5.1%（10.2GB）、int4 71.9±4.7%（7.0GB）。int8 掉分不是精度问题而是**速度问题**——它把频率拖到 1.2Hz，改变了系统动力学；改用阻塞控制剥离速度因素后，三种精度成功率相当（70.0 / 74.4 / 68.8%）。

**消融**：
- 去掉 OpenX 训练（只在 Bridge 上训练）：平均成功率 76.3%→45.6%（**-30 个百分点**），是最重要因素；
- 去掉 DINOv2（仅 SigLIP）：45.6%→40.6%（-5 个百分点），双编码器有增益但非决定性；
- 冻结 vs 微调视觉编码器：46.7% vs 80.0%（详见 3.5 节）；
- LIBERO 仿真微调：OpenVLA 平均 76.5%（排名 1.5）> Octo 75.1%（排名 2）> Diffusion Policy 72.4%（排名 2.5）——但优势远小于真机微调，论文认为原因是 OpenVLA 预训练完全是真机数据，存在仿真域差距。

## 6. 局限性

1. **仅支持单图像观测**：无本体感知（proprioception）、无历史、无多相机——与真实机器人异构的传感器配置不匹配；扩展到交错图文预训练的 VLM 是方向。
2. **推理吞吐不足以支撑高频控制**：ALOHA 等平台需要 50Hz，OpenVLA 6Hz 远不够；动作分块、投机解码是候选方案。
3. **可靠性不足**：虽优于所有基线，但多数任务成功率 <90%，尚不适合无人监督部署。
4. **设计问题未穷尽**：受算力限制，VLM 底座尺寸对 VLA 的影响、动作预测与互联网数据协同训练的作用、最适合 VLA 的视觉特征等问题仍待研究（论文谦称为社区留下开放题）。
5. **只做了机器人数据微调**：没有像 RT-2 那样协同微调，因此语义泛化弱于 RT-2-X。

## 7. 对无人机端到端导航的启示

**（1）观测接口**。OpenVLA 是最接近工程现实的参照：单张 224×224 图像 + 文本指令即可推理，意味着「机载单目相机 + 语言指令」在算力与显存上可行（int4 仅 7GB、可下放到 4090 级 GPU）。但它的两大局限恰是无人机不能接受的：单帧观测无法估计速度与运动趋势，无 IMU 融合难以抗高动态机动。因此无人机版 OpenVLA 最自然的扩展是：多历史帧输入（RT-1 已证明历史帧对对抗干扰与动态判断至关重要）+ IMU/高度/速度状态向量投影进语言 token 空间。

**（2）动作表示**。两点直接可借鉴：其一，**分位数离散化**替代 min-max 边界——无人机飞行日志普遍存在悬停抖动、异常尖峰等离群动作，用 1%–99% 分位数划桶可避免有效分辨率被少数异常值稀释；其二，7 维末端位姿增量与四旋翼 4 维控制（推力+三轴角速率）或航点增量（$\Delta x, \Delta y, \Delta z, \Delta yaw$）之间只是维度映射问题，token 化流程完全通用。但 6Hz 的单步自回归动作对飞控远远不够，动作分块（一次预测一段轨迹）或离散 token + 高频底层控制器（如 PX4 姿态环）组合是必须的折中。

**（3）控制频率**。OpenVLA 贡献了一个常被忽视的教训：**推理频率本身就是系统动力学的一部分**。int8 量化明明 token 精度不差，却因频率从 5Hz 掉到 1.2Hz 导致精度大跌；对无人机而言，控制周期变化会直接影响稳定性，因此部署优化时必须把推理延迟当作控制参数来评测，而不是只看离线精度。无人机侧的对策链条与论文建议一致：LoRA 小数据集微调（单卡可行）→ int4 量化（显存减半、速度不降）→ 模型编译/投机解码。

**（4）sim-to-real 迁移**。OpenVLA 的两条经验对无人机直接适用：第一，**预训练数据质量优于单纯堆量**——过滤全零动作这一类简单清洗步骤对高频控制策略至关重要，无人机的仿真数据同样需要剔除悬停无操作段、崩溃轨迹；第二，其消融显示「只有真机预训练 → 仿真微调收益有限」（LIBERO），反过来提示无人机应先规划好预训练数据的域覆盖（真机+仿真混合预训练），把仿真到真机的差距在预训练阶段就抹平。此外，OpenVLA 开源代码库（支持 OpenX 格式、LoRA、量化推理、远程推理服务）可直接改造成无人机数据管线：把 OpenX 的 RLDS 数据格式替换为飞行演示集，即可复用其训练-微调-部署全链路。
